# QA Agent Framework: Operating Contract

This repository has the QA agent framework installed (`.claude/qa/`). These rules apply whenever
you do testing work here: planning, designing, executing, triaging, or reporting tests.

## Layers and precedence

| Layer | Lives in | Purpose |
|---|---|---|
| L3 Repo config | `qa.config.json` (repo root) | Environments, repo type, automation stack/runner, enabled packs, ADO settings |
| L2 Product/team packs | `.claude/skills/pack-*/` | Journeys, business rules, test data, glossary (grouped by domain, not per component) |
| L1.5 Repo conventions | `.claude/skills/repo-automation-conventions/` | How *this* repo's automation is written (base classes, page objects, clients, data, naming). Generated by `/qa-learn-conventions` |
| L1 Adapters | `.claude/skills/qa-adapter-*/` | *How* to drive an interface (web, api) |
| L0 Core | `.claude/skills/qa-*` | *How to think*: test design, functional, integration, regression, defects |

When layers disagree, the more specific layer wins: **L3 > L2 > L1.5 > L1 > L0**.
Only packs listed in `qa.config.json → packs` are in scope.

## Repo types

- **app-and-tests**: application code and its tests live here. Regression starts from this repo's diff.
- **tests-only** (`"repoType": "tests-only"`): an automation monorepo; the application lives in other
  repos. Existing automated tests are the primary asset:
  - `.qa/catalog.json` indexes every existing test via stack drivers (Java TestNG/JUnit, JS/TS Playwright/Jest/
    Vitest/Cypress/Mocha, Python pytest, .NET NUnit/xUnit/MSTest, Gherkin). Search it with
    `index-tests.mjs --search`. Never read test source in bulk.
  - `.qa/module-map.json` lists the components. `testPaths` are generated; teams fill in `areaPaths`
    (ADO) and `appRepos` (app repo + paths), which let ADO items and app PRs drive regression.
  - YAML cases in `.qa/cases/` are for *new* or *manual* designs only. Don't mirror existing automated
    tests into YAML.

## Working at scale (large repos, 75+ components)

1. **Never load a whole repo or a whole component.** Work from the catalog, the module map, the diff
   `--stat`, and Grep/Glob. Open only the files you need.
2. **Script output is bounded by design.** Full lists go to files (`.qa/selections/*.json`,
   `run.json`); read them selectively (e.g. with `node -e`) and never `cat` large JSON.
3. **Fan out per component.** When a task spans many components (pack drafting, convention learning,
   triage across modules), use parallel subagents with one component or cluster each, and have them
   return summaries.
4. **Triage clusters, not tests.** `parse-results.mjs` groups failures by root cause. Hundreds of red
   tests are usually a handful of causes.

## Hard rules

1. **Read `qa.config.json` first.** If it's missing, stop and suggest `/qa-init`.
2. **Environments.** Only touch environments defined in `qa.config.json`. Never contact an environment
   marked `"blocked": true` or a host in `guardrails.blockedHosts`. Never write (POST/PUT/PATCH/DELETE,
   data-creating form submits) to an environment with `"allowWrite": false`. The PreToolUse hook
   enforces this; don't work around it.
3. **Respect the existing stack.** New automation follows `repo-automation-conventions` (if present),
   `qa.config.json → automation`, and the existing tests next to it. Never introduce a second framework.
4. **Canonical formats.** Cases, runs, defects, and module maps follow `.claude/qa/schemas/`.
5. **Evidence or it didn't happen.** Every executed result has evidence (screenshot, response, stack
   trace, log). A failure with no evidence is `blocked`, not `failed`.
6. **No secrets in files or commands.** Reference env var names only.
7. **Ask before external writes.** ADO writes (test cases, bugs, runs, catalog linking) need explicit
   user confirmation per batch, after a `--dry-run` summary.
8. **Don't guess at business rules.** Unknown expectations are `TBC` and go under open questions.
9. **Test data.** Prefer pack `test-data.md`. Prefix created data with `qa-auto-<runId>-`.

## Workflow and roles

| Step | Command | Subagent | Output |
|---|---|---|---|
| Bootstrap | `/qa-init` | — | `qa.config.json`, `.qa/`, catalog + module map (tests-only), CLAUDE.md import |
| Learn house style | `/qa-learn-conventions` | Explore (parallel) | `.claude/skills/repo-automation-conventions/` |
| Knowledge pack | `/qa-new-pack <domain>` | Explore (per component) | `.claude/skills/pack-<domain>/` |
| Plan | `/qa-plan <ADO id / PR / text>` | `qa-planner` | `.qa/plans/<slug>.md` |
| Design | `/qa-design <plan or scope>` | `qa-designer` | new automated tests and/or `.qa/cases/**.yaml` |
| Execute | `/qa-run <selection>` | `qa-executor` | `.qa/runs/<runId>/run.json` + evidence |
| Regression | `/qa-regress <change source>` | planner → executor | impact-selected run |
| Triage | (part of run) | `qa-triager` | classification per cluster, defect drafts |
| Report | `/qa-report [runId]` | `qa-reporter` | `.qa/runs/<runId>/report.md` |
| ADO sync | `/qa-ado <action>` | — | Test Cases (incl. catalog linking), Bugs, Test Runs |

## Helper scripts (zero-install, Node ≥ 18; all print bounded JSON)

| Script | Purpose |
|---|---|
| `detect-stack.mjs` | Languages, frameworks, Java build modules and surefire wiring, test-only hint, ADO from git remote |
| `index-tests.mjs [--search … --module … --group …]` | Build or search the test catalog |
| `build-module-map.mjs [--strategy build\|package\|path\|folder]` | Generate/refresh components (keeps manual fields) |
| `select-regression.mjs` | Changes (ADO items, app PRs/commits, local diff, modules) → components → tests; full list to file |
| `new-run.mjs --env qa` | Create a run folder |
| `make-suite.mjs --selection latest --run <id>` | Runnable commands per build unit and stack (TestNG XML, file:line, -t regex, node ids, --filter) |
| `parse-results.mjs --run <id>` | TestNG / JUnit XML / TRX / Jest JSON → run.json, stack traces, failure clusters |
| `validate.mjs` | Schema checks for config, maps, cases, runs, defects |
| `ado.mjs <cmd> [--dry-run]` | ADO: items, PR files, test cases, catalog linking, bugs, runs |
